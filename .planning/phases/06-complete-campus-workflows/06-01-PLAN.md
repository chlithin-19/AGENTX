# Plan 06-01: Complete Campus Workflows, Real Backend APIs, Durable Tickets & Frontend Connection

## Context & Objectives
Wire all 4 campus agents to real supported data and backend endpoints, replacing static mock arrays with live authorized API endpoints. Maintenance tickets must be genuinely persisted in SQLite `maintenance_tickets`. Subviews must render real backend data, loading states, error recovery, and clear institutional labeling.

## Tasks

1. **Implement Real Atlas Campus API Endpoints (`backend/atlas/index.js`):**
   - `GET /api/atlas/academics/profile`: Authorized academic, skill, and placement profile from `campus.db`.
   - `GET /api/atlas/academics/benchmarks`: Cohort benchmarks across all departments.
   - `GET /api/atlas/facilities`: Active campus facilities and status.
   - `GET /api/atlas/facilities/tickets`: Durable maintenance tickets from SQLite `campusRepo`.
   - `POST /api/atlas/facilities/tickets`: Create durable maintenance ticket in SQLite `campus.db` with user binding.
   - `GET /api/atlas/events`: Upcoming events, hackathons, and registration caps.
   - `POST /api/atlas/events/:eventId/register`: Real event registration workflow.
   - `GET /api/atlas/circulars`: Institutional circulars and administrative advisories.

2. **Connect Frontend Campus Subviews to Live APIs:**
   - `AcademicsView.jsx`: Fetch from `/api/atlas/academics/profile` and `/api/atlas/academics/benchmarks` with loading skeleton and error state.
   - `CampusView.jsx`: Fetch from `/api/atlas/facilities` and `/api/atlas/facilities/tickets`; post durable maintenance tickets to `/api/atlas/facilities/tickets`.
   - `EventsView.jsx`: Fetch from `/api/atlas/events` with real-time registered counts and live registration modal/action.
   - `CommunicationView.jsx`: Fetch from `/api/atlas/circulars`.

3. **Automated Campus Workflow Test Suite (`backend/tests/campus_workflows.test.js`):**
   - Test `GET /api/atlas/academics/profile` with student isolation.
   - Test `GET /api/atlas/academics/benchmarks`.
   - Test durable ticket creation and persistence in `campus.db`.
   - Test listing user tickets from SQLite.
   - Test event listing and registration.
   - Test circulars listing and filtering.

## Acceptance Criteria
- [x] All 4 campus agents have real backend REST endpoints mounted on `/api/atlas/*`.
- [x] Maintenance tickets are genuinely persisted in SQLite `maintenance_tickets` table (not an in-memory array).
- [x] Frontend subviews fetch live data from backend with loading/error handling.
- [x] All automated workflow tests pass with 0 failures; frontend builds cleanly.
