# Plan 01-01: Security and Authentication Hardening

## Context & Objectives
Audit the completed security baseline from commit `71a70db`, correct remaining cryptographic and parameter tampering vulnerabilities, enforce strict fail-closed production behavior, and verify point-of-access student isolation, department-scoped faculty RBAC, and replay-prevented confirmation actions.

## Tasks

1. **Harden Cryptographic Token Verification (`backend/atlas/security/identity.js`, `config.js`):**
   - Pin algorithm strictly to `alg === 'HS256'`. Reject any other algorithm (including `'none'`) immediately.
   - Enforce mandatory expiration: reject any token without a valid numeric `exp` timestamp in the future.
   - Check `nbf` (not before) if present.
   - Support optional `iss` (issuer) and `aud` (audience) verification when configured in `AUTH_CONFIG`.
   - Ensure `ATLAS_JWT_SECRET` must be at least 32 characters in production when configured.
   - Ensure payload contains verified identity (`sub` or `id`/`studentId`) and valid role.

2. **Eliminate Parameter Overrides (`backend/atlas/index.js`):**
   - Remove `overrideUser` fallback from `POST /api/atlas/orchestrate`.
   - Exclusively rely on `req.user` validated by `extractIdentity` middleware.

3. **Harden Action Confirmation User Binding (`backend/atlas/security/confirmation.js`):**
   - Normalize user comparison across `id`, `studentId`, and `sub` fields (`reqUser.id || reqUser.studentId || reqUser.sub`).
   - Retain atomic replay lock (`record.consumed = true`) on side-effect errors.

4. **Verify Point-of-Access Student Isolation (`backend/atlas/security/authorization.js`, `academic.js`):**
   - Confirm `assertStudentAccess` is called at the data access point.
   - Ensure cross-student or cross-department access returns generic 403 Forbidden without leaking private information.

5. **Automated Security Test Suite Expansion (`backend/tests/security.test.js`):**
   - Add unit tests for algorithm tampering, missing expiration timestamps, audience/issuer mismatches, and body identity spoofing attempts.
   - Run complete suite via `node --test tests/security.test.js`.
   - Run Vite production build to ensure 0 frontend bundle regressions.

## Acceptance Criteria
- [x] Unsafe production configs fail closed at startup.
- [x] Client simulation headers in production return HTTP 400.
- [x] Unauthenticated production requests return HTTP 401.
- [x] Algorithm confusion attacks and unsigned tokens are rejected.
- [x] Tokens without `exp` are rejected.
- [x] Cross-student access is blocked with 403 without data leakage.
- [x] Faculty access is strictly department-scoped.
- [x] Confirmation tokens execute stored proposals; replay attempts blocked.
- [x] All automated tests pass with 0 failures; frontend builds cleanly.
