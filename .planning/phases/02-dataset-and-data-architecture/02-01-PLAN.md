# Plan 02-01: Dataset Ingestion, Validated Relational Architecture & Authorized Repositories

## Context & Objectives
Discover, extract, and ingest the campus placement dataset from `archive.zip` into a validated, relational SQLite database (`backend/data/campus.db`) using Node.js's native `node:sqlite`. Establish typed repository layers with parameterized queries and point-of-access authorization enforcement. Ensure clear provenance and strict separation between historical benchmark data and student private records.

## Tasks

1. **Schema Definition (`backend/atlas/campus/schemas/schema.sqlite.sql`):**
   - Create tables: `departments`, `students`, `student_academic_records`, `student_skill_profiles`, `student_placement_records`, `cohort_benchmarks`, and `maintenance_tickets`.
   - Add indices on `students(student_id)`, `students(branch_code)`, `academic_records(student_id)`, `maintenance_tickets(id)`.
   - Enforce check constraints and foreign keys.

2. **Reproducible Dataset Ingestion Pipeline (`backend/atlas/campus/ingestion/ingestDataset.js`):**
   - Extract `student_placement_prediction_dataset_2026.csv` from root `archive.zip` if unextracted.
   - Parse CSV with row validation: type checks, range checks (CGPA [0-10], attendance [0-100], backlogs >= 0), and null checks.
   - Batch insert into SQLite database using transactions for fast ingestion (< 3 seconds for 10,000 rows or configurable limit, defaults to representative cohort with option for full 100k).
   - Compute and store cohort aggregate benchmarks (CSE, IT, ECE, EEE, Mechanical, Civil).
   - Record provenance metadata: `source: 'student_placement_prediction_dataset_2026.csv'`, `ingested_at`, `record_count`.

3. **Authorized Repository Layer (`backend/atlas/campus/repositories/`):**
   - `studentRepo.js`: `getStudentById(id, requestingUser)` - parameterized query `SELECT ... FROM students WHERE student_id = ?`, guarded by `assertStudentAccess`.
   - `academicRepo.js`: `getAcademicRecord(studentId, requestingUser)` - parameterized query `SELECT ... FROM student_academic_records WHERE student_id = ?`, guarded by `assertStudentAccess`.
   - `placementRepo.js`: `getPlacementProfile(studentId, requestingUser)`, `getCohortBenchmarks(branch)` - returns student skills and benchmark statistics.
   - `campusRepo.js`: Durable maintenance ticket operations (`createTicket`, `getTicketById`, `listTicketsByReporter`).
   - `index.js`: Unified repository exports and database initialization helper.

4. **Connect Agents to Authorized Repositories (`backend/atlas/agents/`):**
   - Update `AcademicAgent` to query `academicRepo` and `studentRepo` while maintaining fallback to demo data if DB is uninitialized.
   - Update `CampusAgent` to persist maintenance tickets via `campusRepo`.

5. **Automated Data Architecture Test Suite (`backend/tests/data_architecture.test.js`):**
   - Test CSV extraction and ingestion validation (invalid values rejected).
   - Test parameterized queries and indexing performance.
   - Test point-of-access isolation: student cannot query another student's record through repository.
   - Test department-scoped faculty RBAC through repository queries.
   - Test maintenance ticket durability and retrieval.
   - Test cohort benchmark aggregation accuracy.

## Acceptance Criteria
- [x] Ingestion pipeline extracts and validates `archive.zip` CSV without data loss.
- [x] Schema enforces relational integrity, indices, and constraints.
- [x] Benchmark statistics are strictly separated from individual student records with explicit classification labels.
- [x] Repositories use parameterized queries and enforce `assertStudentAccess`.
- [x] Cross-student access through repositories returns 403 Forbidden.
- [x] All automated tests pass with 0 failures; frontend production build passes.
